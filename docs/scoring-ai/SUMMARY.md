# ScoringAI 한 장 요약 (팀 공유용) — 2026-11-03 기준 v2.1

> 담당: 남재은 · 브랜치 `JANENAMMMM/scoring-ai` · 상세: `judge_spec_v2.md`, `orchestration_log.md`

## 무엇을 만들었나

관광지별 **여행 난이도 1~10점 + 하한·상한(방문 방식에 따른 폭)** 을 근거와 함께 산출하는 ScoringAI.

```
근거 DB(Supabase scoring_*) ──▶ LLM judge(Claude, 도구 호출 + 웹 검색) ──▶ 인용 검증 코드 ──▶ 점수 DB
  523개 근거·1,994개 리뷰        대표 관람 경로 → 차원별 점수·조건       인용 ID 실재·수치 일치      15곳 × 3회 중앙값
```

- **차원 4개**: 계단·오르막 / 보행량 / 더위 / 혼잡 (각 typical·lower·upper)
- **하한·상한에는 조건이 붙는다**: 예) 오행산 하한 4 = "엘리베이터 이용(15,000동), 동굴 1곳만, 오전" → 일정 짜기가 조건을 골라 피로도를 낮출 수 있음
- **종합 점수는 코드가 계산**(계단·보행 3, 더위 2, 혼잡 1 가중평균). 표시용 등급 1~3 하 / 4~6 중 / 7~10 상
- 판정 근거는 LLM이 해석하지만, **인용이 없거나 DB에 없는 근거를 쓴 실행은 무효**

## 믿을 수 있나

- **인용 검증**: 재실행 18회 전부 통과. 1차 실행 실패 9회는 원인(출력 형식 이탈, URL 표기 차이)을 고치고 재실행
- **v1 규칙 엔진과 비교**: 13곳 중 8곳 등급 일치. 다른 곳은 v2가 웹 검색으로 v1이 못 본 근거를 찾은 경우(영흥사 계단, 누이탄타이 경사) 또는 v1이 리뷰 언급률만으로 '중'을 준 경우(미케·용다리·야시장)
- **다른 모델 교차검증(v1 시점)**: 서로 다른 모델끼리 8/15만 일치 → LLM 단독 판정의 흔들림을 확인, 그래서 인용 검증·3회 중앙값·고정 앵커를 둠
- **남은 검증**: 사람 기준셋 (`gold_set_template.md`, 팀원 2명 × 30분)

## 다른 기능에서 쓰는 법

- **일정 짜기**: `scoring_scores`(또는 `data/scoring/scores_v2.json`)의 차원별 typical/lower/upper + 조건. 하루 합이 부모님 프로필 허용치를 넘으면 가장 높은 곳부터 lower 조건 적용
- **챗봇**: `conditions`, `rationale`, 인용 근거 ID로 "왜 힘든지" 설명 (`scoring_evidence`, `scoring_reviews` 조회)
- **UI**: 등급 카드 + "엘리베이터 이용 시 4점" 같은 하한 조건 표시

## 비용·데이터 현실

- 15곳 × 3회 + 재실행: 약 $9 (Claude Sonnet, 웹 검색 포함)
