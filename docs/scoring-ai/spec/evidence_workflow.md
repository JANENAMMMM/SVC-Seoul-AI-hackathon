# ScoringAI 근거 검증과 상품 일정 연결

## 관계자에게 보여줄 최소 화면

**관광지·관람 방식·점수**, 힘든 이유 1~2개, 부담을 줄이는 조건, 출처 링크, 검수 상태만 보여준다. 내부의 실행 ID·가중치·리뷰 대조표는 근거를 열어 볼 때 제공한다. 현재 점수는 50세 이상 여행자의 체감 점수로 검증된 결과가 아니라, 보통 체력을 가정한 설계 점수다.

## 1. 점수와 설명의 출처

v2.1 점수와 기존 `scores_v2.json`은 바꾸지 않았다. `visit_modes_v2_1.json`을 생성할 때 각 차원의 **최종 typical/lower/upper 점수 세 개와 모두 일치하고 인용 검증을 통과한 실행**을 선택한다. 해당 실행의 조건·근거 ID·실행 ID를 함께 담는다. 현재 15곳 × 4차원은 전부 정확히 일치하는 실행이 있다. 없으면 설명을 임의로 붙이지 않고 생성이 실패한다. 향후 재채점 CLI는 기존 공개 점수를 우발적으로 1회 실행으로 덮지 않도록 `--replace`를 요구한다.

`scores_v2.json`의 기존 `conditions`는 과거 첫 실행에서 가져온 필드라 차원별 최종 중앙값과 다를 수 있다. **상품 화면에서는 새 관람 방식 카탈로그의 조건을 사용한다.** DB의 기존 v2.1 행은 이번 작업에서 바꾸지 않았다.

## 2. 채점에 쓰지 않은 후기 검증

`heldout_review_annotations.csv`에 **후기 1건당 1행**을 작성한다. 평가자는 AI 점수를 보지 않고, 후기에서 실제 확인되는 차원만 1~10점으로 기록한다. 언급이 없으면 빈 칸으로 둔다. `mode`는 해당 후기가 설명하는 관람 방식(`standard/short/full`)을 확인한 경우에만 선택한다. 확인이 불가능하면 점수 비교에 넣지 말고 별도 조사 메모로 보관한다. `source_url`은 원문 확인 링크, `review_id`는 플랫폼의 고유 ID, `review_text`는 중복 판별용 원문이다.

`python -m src.scoring.run_review_validation docs/scoring-ai/validation/heldout_review_annotations.csv --output <보고서.json>`으로 차원별 표본 수, ±1점 이내 건수, 평균 절대오차, 개별 불일치 근거를 생성한다. 기존 수집 Tripadvisor 리뷰와 ID 또는 원문이 같으면 제외한다. 차원·방식별 표본이 **3건 미만이면 `insufficient`**로 표시한다. 이 보고서는 후기에서 관찰한 조건과 점수의 대조이지, 50세 이상 고객의 실제 체감 검증은 아니다. 후기에 등장하지 않는 어려움이 없다고 해석하지 않는다.

## 3. 하나투어 일정표 연결

일정표를 받으면 방문 순서마다 `place_id`, `mode`, `source_ref`(일정표 파일·쪽·행), `route_note`(예: 엘리베이터 사용, 동굴 생략)를 기록한다. `evaluate_itinerary(days, catalog)`는 네 항목이 없으면 점수를 내지 않는다. 관람 방식은 자동 추정하지 않는다. 결과에는 일차별 점수와 패키지 최고·평균, 사용한 일정표 근거, `needs_review` 관광지 목록이 들어간다. 현재 연속 가산은 방문 순서 기준의 **시뮬레이션 규칙**이므로, 실제 상품의 체류·휴식 시간이 확인되기 전에는 고객 체감 개선 수치로 홍보하지 않는다.

입력 JSON의 최소 형태는 `{"days": [[{"place_id": "dad-02", "mode": "short", "source_ref": "일정표.pdf p.2", "route_note": "엘리베이터 이용·사원 일부"}]]}`다. 이 값은 **형식 예시**이며 실제 상품 동선이 확인됐다는 뜻이 아니다. `python -m src.scoring.run_itinerary <입력.json> --output <결과.json>`으로 계산한다.

서비스 호출은 `GET /api/scoring/places`(목록·방식별 점수), `GET /api/scoring/places/{place_id}`(차원·근거 ID·조건), `POST /api/scoring/packages/evaluate`(위 JSON 형식)로 제공한다. 현재 저장된 v2.1 카탈로그를 읽으며 API 비용·DB 쓰기는 없다.

## 출시 전 확인해야 할 한 가지

가이드·상품기획자가 실제 일정의 10~15곳을 AI 점수를 보지 않고 평가하고, 차원별 ±1점 이내 비율과 큰 불일치 사례를 함께 공개한다. 이때 관람 방식·방문 계절·하차 위치를 같은 조건으로 맞춘다. 그 자료가 있어야 “50세 이상 여행자에게 설득력 있는 점수”라고 주장할 수 있다.
