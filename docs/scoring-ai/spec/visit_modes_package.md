# ScoringAI v2.1 관람 방식과 패키지 난이도

`data/scoring/visit_modes_v2_1.json`은 기존 `scores_v2.json`과 검증된 `judge/v2` 실행 기록으로부터 만든 15곳 × 3방식의 정적 스냅샷이다. API 호출이나 추가 수집은 없다. 각 관광지에는 `standard`(기존 typical), `short`(이동 보조·짧은 관람), `full`(긴 도보·전체 관람)이 있다. 각 방식의 4차원 점수와 근거 ID, 적용 조건을 포함한다. `standard` 점수는 기존 v2.1 typical 종합점수와 같다.

방식별 점수는 climb·walking에 해당 lower 또는 upper 조건을 적용하고, heat·crowd는 typical을 유지해 3:3:2:1 가중 평균을 반올림한다. 시간·계절 조건을 임의로 혼합하지 않기 위해서다. 해당 차원의 lower/upper 조건이 없으면 typical을 사용한다. 따라서 이 방식들은 특정 날짜·시간·현장 동선을 확정한 점수가 아니다. 특히 `needs_review`인 참 조각 박물관과 껌탄 코코넛 마을의 상태는 그대로 유지한다. 오행산 `short`는 엘리베이터가 일부 계단만 생략한다는 근거에 따라 5점이며, `full`은 열·혼잡을 typical로 둔 7점이다. 7월 한낮의 upper 열 조건까지 동시에 적용한 9점짜리 관람 방식으로 읽으면 안 된다.

`src/scoring/package_difficulty.py`의 `calculate_package(days, catalog)`에 일차별 방문 순서와 관광지 ID·방식 ID를 넣는다. 하루 기본값은 그날 최고 관광지 점수다. **6점 이상 방문이 연속한 인접 쌍**마다 1점, 하루 최대 2점을 더해 10점에서 제한한다. 휴식 시간이나 실제 이동시간 자료가 없으므로 현재의 연속 여부는 일정 순서만으로 판단한다. 패키지는 일차별 난이도, 최고 난이도(`peak`), 일차 난이도의 산술평균(`mean`, 소수 첫째 자리)을 함께 반환한다. 평균을 1~10 정수로 볼 수 있도록 `mean_rounded`도 제공한다.

## 예시 일정

| 일차 | 방문 순서 | 기본값 | 연속 가산 | 일차 난이도 |
|---|---|---:|---:|---:|
| 1일차 | 바나힐 표준(6) → 오행산 전체(7) | 7 | 1 | 8 |
| 2일차 | 호이안 구시가지 표준(4) → 호이안 야시장 표준(3) | 4 | 0 | 4 |

패키지 최고 난이도는 **8**, 일차 평균은 **6.0**이다. 1일차 오행산을 `short`인 **엘리베이터·사원 일부(5)**로 바꾸면 6점 이상 방문이 이어지지 않아 1일차 **6**, 패키지 최고 **6**, 평균 **5.0**이 된다. 이는 일정 예시의 계산 결과이며 현장 검증 결과가 아니다.

재생성: 저장소 루트에서 `scores_v2.json`을 읽어 `build_modes(scores, Path('data/scoring/judge/v2'))`를 호출한다. 구현과 스냅샷 일치는 `tests/test_visit_modes_package.py`에서 검사한다.
