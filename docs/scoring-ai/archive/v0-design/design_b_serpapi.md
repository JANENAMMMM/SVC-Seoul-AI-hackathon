# ScoringAI 설계안 B — SerpApi 리뷰 기반 (검토용)

> 담당: 남재은 · 상태: **팀 검토 요청** · v0.2(측정 데이터 기반)와 비교용 대안
> 핵심 아이디어: Google 공식 API의 "리뷰 5건" 한계를 SerpApi로 풀고, **관광지당 수백 건의 리뷰에서 차원별 부담 언급을 통계적으로 집계**한다.
> "리뷰만 쓰면 신뢰도가 낮다"는 비판에는 ① 표본 크기와 신뢰구간 ② 문장 단위 근거 ③ 외부 라벨(Viator)·사람 기준셋과의 교차 검증으로 답한다.

---

## 0. 검토 요청 사항

| # | 결정 필요 | 제안 |
|---|---|---|
| 1 | 데이터 | SerpApi `google_maps_reviews`로 관광지당 **리뷰 200건 이상** (한·영 각 100건+) |
| 2 | 평가 차원 | 리뷰에서 실제로 언급되는 6개: 걷는 양, 계단·오르막, 더위·그늘, 대기·혼잡, 쉴 곳, 노면 |
| 3 | 판정 방식 | 리뷰 문장 단위로 sLLM이 차원별 **부담 언급 여부 + 강도 + 근거 문장** 추출 → 코드가 비율·신뢰구간 계산 |
| 4 | 등급 | 차원별 언급 비율 → 0~3 → 가중합 → 상·중·하 (판정은 코드) |
| 5 | 검증 | Viator `PHYSICAL_EASY/MEDIUM/HARD` 라벨 + 팀 기준셋 20곳과 일치도 |
| 6 | 약관 리스크 | 해커톤 시연용. 운영 단계는 하나투어 협업·공식 데이터로 전환한다고 발표에 명시 |

## 1. 데이터 수집

### 1-1. SerpApi로 가져오는 것 (공식 문서 확인)

| 항목 | 내용 |
|---|---|
| 엔진 | `google_maps_reviews` (장소는 `data_id` 또는 `place_id`로 지정) |
| 페이지당 | `num` 1~20 (기본 10) |
| 페이지 넘김 | `next_page_token`. 전체 건수 상한은 문서에 없음 |
| 정렬 | `sort_by`: `qualityScore`(기본) / `newestFirst` / `ratingHigh` / `ratingLow` |
| 언어 | `hl=ko`, `hl=en` |
| 필터 | `query`(리뷰 키워드 검색) 또는 `topic_id`(Google 자동 주제), 동시 사용 불가 |
| 캐시 | 1시간 내 같은 요청은 무료 |

출처: https://serpapi.com/google-maps-reviews-api

### 1-2. 수집 전략

```
관광지 1곳당
  ① 전체 리뷰: sort_by=newestFirst, hl=ko 최대 100건 + hl=en 최대 100건   → 분모(표본)
  ② 키워드 리뷰: query="계단", "stairs", "더워", "hot", "줄", "queue" …      → 근거 보강
```

- **최신순**으로 받는 이유: 관련도순은 Google이 고른 "좋은 리뷰"에 쏠릴 수 있음. 최신순이 표본 편향이 적음
- ②는 비율 계산에 쓰지 않는다 (키워드로 걸러진 표본이라 분모가 왜곡됨). 근거 문장 확보용
- 리뷰 원문은 분석 후 **점수와 근거 요약만 저장**, 원문은 장기 보관하지 않음 (약관 리스크 축소)

### 1-3. 비용 (20곳 기준)

| 항목 | 호출 수 |
|---|---|
| 전체 리뷰 200건 ÷ 20건/페이지 | 10회 × 20곳 = 200회 |
| 키워드 리뷰 6차원 × 1페이지 | 6회 × 20곳 = 120회 |
| 합계 | **약 320회** |

- 무료 250회/월(2차 자료 기준) → 부족. **유료 1개월($25, 1,000회)** 이면 재실행 포함 충분
- 페이지당 1회 차감인지는 공식 문서에 없음 → 첫날 소량 실행으로 확인

**정리**

- 해커톤: Tripadvisor·Reddit은 **연구·시연 목적, 원문 비보관, 집계값만 저장**으로 리스크를 낮춰 사용. 발표에서 이 점을 명시
- 실서비스: 외부 스크래핑 데이터는 쓰지 않는다. **Google 공식 + OSM + 네이버 + 하나투어 자체 후기·가이드 입력(L3)** 구조로 전환
- 발표 메시지: "시연은 공개 리뷰로 방법론을 검증했고, 실서비스는 하나투어가 이미 가진 고객 후기와 가이드 데이터로 같은 파이프라인을 돌린다" → 멘토가 말한 "부족한 부분은 하나투어와 협업" 실행 계획과 연결

## 2. 평가 차원 (리뷰에서 실제로 측정되는 것만)

| 차원 | 부담 언급 예 (한/영) | 0 / 1 / 2 / 3 (언급 비율, 초기 가정) |
|---|---|---|
| 걷는 양 | 많이 걸어요, 다리 아파요 / a lot of walking | <5% / 5~15% / 15~30% / 30%+ |
| 계단·오르막 | 계단 많음, 오르막 / steep, stairs | 〃 |
| 더위·그늘 | 땡볕, 그늘 없음 / so hot, no shade | 〃 |
| 대기·혼잡 | 줄 길어요, 사람 너무 많음 / long queue, crowded | 〃 |
| 쉴 곳 | 앉을 데 없음 / nowhere to sit | 〃 |
| 노면 | 미끄러워요, 모래 / slippery, uneven | 〃 |

- **"쉴 곳"을 식당·카페 수로 판단하지 않는다.** 붐비는 테마파크는 식당이 많아도 앉을 곳이 없다 → 방문자가 직접 "앉을 데 없다"고 말한 비율로 측정
- **"걷는 양"을 체류 시간으로 판단하지 않는다.** 방문자가 "많이 걸었다"고 말한 비율로 측정
- 반대 언급("계단 없어서 편해요", "엘리베이터 있음")은 **완화 언급**으로 따로 세어 순비율에 반영

```
부담 비율 = (부담 언급 리뷰 − 완화 언급 리뷰) / 전체 리뷰    (0 미만은 0)
```

## 3. 판정 파이프라인

```
리뷰 200건+ ─▶ ① 문장 분리
              ─▶ ② 규칙(키워드 사전)으로 후보 문장 표시
              ─▶ ③ sLLM: 문장별 {차원, 부담/완화/무관, 강도 1~3, 근거 span}  ※ JSON 고정 스키마
              ─▶ ④ 코드: 차원별 비율 + Wilson 95% 신뢰구간
              ─▶ ⑤ 코드: 0~3 변환 → 가중합 → 부담 지수 → 상·중·하
              ─▶ ⑥ LLM 2차 검토: 근거 문장과 점수가 맞는지, 광고·반어 오분류 지적
              ─▶ DB(draft) ─▶ 담당자 검수 ─▶ confirmed
```

| 단계 | 누가 | 이유 |
|---|---|---|
| ② 후보 표시 | 규칙 | 빠르고 재현 가능. sLLM 호출 수 절감 |
| ③ 문장 판정 | sLLM | "계단은 많지만 경치 덕에 안 힘들었다" 같은 문맥 판단은 규칙으로 불가 |
| ④⑤ 집계·등급 | 코드 | 같은 입력이면 같은 출력. 판정 근거를 숫자로 설명 가능 |
| ⑥ 검토 | LLM | 판정자가 아닌 검토자. 이상치만 사람에게 넘김 |

**신뢰성 장치**

- 표본 **최소 100건** 미만이면 등급 대신 "정보 부족"
- 신뢰구간 폭이 20%p 이상인 차원은 점수 범위를 ±1로 표시
- 각 차원 점수에 **근거 리뷰 문장 3개**를 붙여 저장 → 챗봇·UI에서 그대로 보여줌
- sLLM 판정 품질 점검: 팀이 리뷰 문장 200개를 직접 라벨링 → sLLM 정확도 보고

## 4. 등급 산정

```
부담 지수 = 100 × Σ(가중치 × 점수) / (3 × Σ가중치)
가중치 초안: 계단·오르막 3 · 걷는 양 3 · 더위 2 · 쉴 곳 2 · 대기 1 · 노면 1
등급: 0~33 하 / 34~66 중 / 67~100 상
```

- 가중치 근거: 계단 오르기 6.8 MET vs 평지 보행 3.5 MET(2024 Compendium), 고령층 관광지 불편 1위 경사·계단 23.1%(경기연구원 2024)
- 비율 구간(5/15/30%)과 가중치는 **기준셋으로 보정**하는 가정값

## 5. 검증 — "리뷰만으로 믿을 수 있나"에 대한 답

| 검증 | 방법 | 발표에서 보여줄 것 |
|---|---|---|
| 외부 라벨 | Viator Partner API의 `additionalInfo.type` 중 `PHYSICAL_EASY/MEDIUM/HARD`(공식 스펙 확인)를 같은 관광지 투어에서 수집 | 우리 등급과 Viator 라벨 일치율 |
| 사람 기준셋 | 팀원 2명이 20곳을 독립 판정 | 사람 간 일치도, 자동 vs 사람 일치율 |
| sLLM 정확도 | 리뷰 문장 200개 수작업 라벨 | 문장 판정 정확도 |
| 안정성 | 다른 날짜·다른 표본으로 재수집 | 등급 변동 여부 |

- Viator 라벨은 **투어 상품 단위**(공급자가 설정)라 관광지와 1:1이 아님 → "약한 참고 라벨"로만 사용
- 불일치 건은 원인(표본 부족 / 문화 차이 / 가중치)을 표로 정리 → 가중치 보정 후 `rubric_version` 올림
