# 2026-11-02 최종 회의 (1일차 멘토링 후, 약 30분)

> 원문: 노션 To-do list › 마지막 최종 회의내용(약30분)

## 결정 사항

1. **관광지 난이도는 사전 평가 후 DB로 구축**
   - 관광지 정보를 미리 수집하고, 팀이 설계한 기준으로 LLM이 난이도를 평가해 DB에 저장한다
   - 서비스 이용 시 실시간 생성하지 않고 사전에 검증된 데이터를 조회한다
   - 평가 담당은 **스코어링 AI**(개발 단계에서 배치 실행), 사용자 요청 처리는 **챗봇**(서비스 런타임)으로 구분한다
2. **평가 기준과 입출력을 명확히 설계**
   - LLM-as-a-judge 방식: 평가 기준(루브릭)·입력 정보·출력 형식(JSON)·판단 근거를 명시한다
   - 리뷰와 관광지 정보를 평가 자료로 쓰고, 별도 LLM으로 결과를 재검토(검증)한다
   - 목표: "함수처럼" 입력이 정해지면 출력과 근거를 설명할 수 있어야 한다
3. **관광지와 식당은 분리**
   - 관광지: 정보 수집 → 난이도 평가 → DB 구축까지 한 작업 범위 (불변 데이터)
   - 식당: 선택한 관광지 주변을 실시간 검색·조회 (음식 종류, 대표 메뉴). 리뷰 분석은 여유 있을 때
4. **개발 순서: DB·스코어링 → 챗봇 → UI**
   - 초기에는 목업 데이터로 설계 가능
   - 각 기능은 호출하기 쉽게 감싸서(서비스 단위) 제공하고, 먼저 끝난 사람이 다른 작업을 지원한다
5. **핵심 기능에 집중**: 다른 서비스에서 더 편한 기능은 복제하지 않는다. 지도 시각화는 미확정
6. **발표 관점**: 부모님을 여행의 주인공(독립된 여행자)으로, 자녀는 걸음을 맞춰 돕는 사람으로. 30초~1분 스토리텔링
7. **협업 방식**
   - 각자 브랜치에서 작업 → PR, 통합용 develop 브랜치 운영
   - 설계는 혼자 끝까지 만들고 공유해 피드백. 공유 시 "검토할 핵심 + 요약"만 정리
   - 개인 Markdown 보고서는 정해진 위치에 저장
   - 디스코드는 바로 답 못 해도 확인 표시
