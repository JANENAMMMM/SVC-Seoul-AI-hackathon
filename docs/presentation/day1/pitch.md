## ① 문제와 고객: 어떤 고객이 어떤 상황에서 불편을 겪는가 (약 1분 30초)

### 고객

| 구분 | 누구 | 근거 |
|---|---|---|
| **주 고객** | 부모님(**50대 이상**) 해외여행을 준비하는 **20~40대 자녀** | 고령자가 여행 정보를 **가족·친구에게 얻는 비율 71.4%** (경기연구원 2024, 고령자 238명) |
| 당사자 | 함께 가는 부모님. 3대 가족이면 조부모·아이까지 | 주최측: "부모님 = 보행 약자로 한정 말 것", 이도경 멘토: "조사한 문제가 특정 연령대에 해당하면 그 연령을 타깃으로 잡아도 된다" |

> 타깃 연령은 **50대 이상 부모님**으로 잡는다. 50~60대는 패키지 비중이 높고 자연·유적·온천처럼 걷는 양이 많은 테마를 선호한다(오픈서베이 2025). 그래서 "패키지 + 체력 부담" 문제가 고령층만의 문제가 아니라는 점에서 출발한다. 다만 판단 기준은 나이가 아니라 **가족 중 가장 체력이 약한 사람**에 둔다. 그래서 3대 가족으로 확장할 수 있다.

### 상황: 자녀가 패키지나 직접 짠 일정을 보고 "이거 부모님께 무리 아닐까?"를 판단해야 할 때

**불편 ①  일정표만 봐서는 하루가 얼마나 힘든지 알 수 없다**
- 60대의 **63.3%가 패키지**를 선택하고, 평균 6.7일로 가장 긴 여행을 간다 (오픈서베이 2025)
- 패키지 일정표에는 "관광지 → 차량 1시간 30분 → 관광지"만 있고, **관광지 안에서의 부담은 산정되지 않는다**. MD는 "코스가 하루에 다 돌아지는지"만 본다 (하나투어 조윤곤 멘토)
- 패키지도 "내려서 걷고, 다시 이동해서 걷기"의 반복이라 도쿄 등은 **하루 2~3만 보** 수준이다 (주최측 설명)
- 효도여행 큐레이션 페이지도 "걷는 양과 쉬는 시간을 직접 비교하라"고만 안내한다 (트립스토어)

**불편 ②  힘든 곳이 "연달아" 붙는 배치를 미리 걸러낼 수 없다**
- 고령자 관광지 불편 1위는 **경사·계단 등 이동 환경(23.1%)**, 여행을 망설이는 요인 1위는 교통 불편이다 (경기연구원 2024)
- 시니어 여행 제약 요인에 **체력 부족**이 있다 (한국관광공사 2022)
- 자녀 후기: "부모님의 괜찮다는 진짜가 아니다", "일정은 50%만 해도 충분" (Threads)

**불편 ③  자녀가 부모님께 일정을 쉽고 설득력 있게 설명하기 어렵다**
- "어디 가고 싶냐"고 물으면 부모님은 "잘 몰라 못 고르겠다"고 답하고, 결국 갈등으로 이어진다 (위키트리 사례)
- 긴 도보나 오르막은 미리 알려 드려야 갈등이 줄어든다 (레이디경향 '부모님 동반 여행 십계명')
- 과제소개서도 문제 3번으로 이 점을 명시한다

> **정의한 문제:** 자녀는 출발 전에 **"이 일정이 부모님께 무리인지"를 판단할 기준이 없다.**

### 여행지: 고객이 실제로 가는 곳 기준 (데이터 유무로 고르지 않음)
- 50대 이상은 **일본·동남아** 수요가 높다. 전체 선호도에서 일본 43.8%, 동남아 39.8%이고, 50~60대는 자연·유적·온천 테마를 선호한다 (오픈서베이 2025)
- 2025년 한국인 인기 해외 도시는 도쿄·후쿠오카·오사카 순이다 (아고다, 전 연령 기준)
- **데모 후보: 일본(후쿠오카·오사카) 또는 베트남(다낭).** 50대 이상 패키지 판매 데이터로 확정하고 싶은 부분이라, 하나투어 멘토께 질문할 예정이다

## ② 해결 아이디어: 현재의 대안과 비교해 무엇이 달라지는가 (약 1분 30초)

### 핵심: 난이도 × 배치 규칙 × 하루 피로도

**1) 관광지 관광 난이도 상·중·하 (DB로 관리)**

| 등급 | 기준 (예시) | 예 |
|---|---|---|
| **상** | 계단·언덕·긴 도보, 그늘·쉴 곳 부족, 긴 대기 | 언덕 위 신사·사원, 대형 야외 유적 |
| **중** | 평지지만 오래 서 있거나 걷는 곳 | 시장, 구시가지 산책 |
| **하** | 앉아서 즐기거나 차량·실내 위주 | 온천, 카페, 마사지, 크루즈 |

- 정밀한 걸음 수는 구할 수 없다. 대신 **누구나 판단하고 고칠 수 있는 3단계 등급**을 쓴다
- **등급 산정 방식** (2단계)
  1. **관광지 자체 속성**: 유형(산·사원·유적·실내 등), 공개 정보의 계단·경사·소요 시간
  2. **구글 리뷰 크롤링 → 규칙 기반 분석**: "힘들다", "오래 걷는다", "계단 많다", "언덕", "줄이 길다" 같은 키워드의 언급 비율로 점수를 낸다
     - 규칙만으로 판단이 어려우면(표현이 다양하거나 언급이 적을 때) **sLLM으로 리뷰에서 부담 요소를 추출**하고, 점수는 **자체 산식**으로 계산한다
  - 두 점수를 합쳐 상·중·하로 나누고, 근거 리뷰를 함께 저장한다

**2) 배치 규칙 (알고리즘)**
- **상 연속 금지**: 상 다음에 바로 상을 배치하지 않는다
- **상 뒤엔 휴식**: 상 다음에는 하(카페·식사·숙소 휴식)를 배치한다
- 하루 상 개수 상한 (가족 프로필에 따라)
- 상은 가급적 오전에 배치한다

**3) 하루 총 피로도**
- 등급 점수의 합에 이동 부담을 더하고 휴식만큼 뺀다 *(예: 상 3·중 2·하 1, 확정 전)*
- 가족 프로필 허용치와 비교해 **여유 / 적정 / 빠듯 / 무리**로 표시하고, 날짜별 그래프로 보여준다
- 위반이 있으면 순서 바꾸기, 휴식 끼우기, 같은 테마의 쉬운 장소로 교체하는 대안을 낸다. **꼭 가고 싶은 곳은 유지**한다

### 현재 대안과 비교

| 현재 대안 | 한계 | 반걸음 |
|---|---|---|
| 패키지 일정표 | 이동 시간만 있고 부담 정보 없음. 고객이 추측해야 함 | 상품마다 **난이도·하루 피로도** 표시 |
| 여행 플래너·지도 앱 | 장소를 지도에 이어 줄 뿐, 피로가 쌓이는 순서는 안 봄 | **배치 규칙**으로 무리한 연속 구간을 찾아 고침 |
| AI 여행 챗봇 | "부모님과 함께"를 문장으로만 반영, 매번 답이 다름 | 등급 DB와 규칙으로 **같은 일정엔 같은 결과** |
| 자녀가 직접 검색 | 블로그·후기를 반복해서 뒤짐 | 근거 리뷰가 붙은 등급과 큰 글씨 카드로 부모님께 바로 공유 |

## ③ AI 활용 방식: 어떤 입력을 받아 어떤 결과를 제공하는가 (약 1분)

```
[입력]                          [처리]                               [결과]
일정 (패키지 일정표            ① LLM: 일정표 → 방문지 목록 정리       · 날짜별 피로도 그래프
     붙여넣기/캡처,            ② 난이도 DB 조회                      · 위반 지점 + 이유
     또는 가고 싶은 곳)           └ DB에 없으면 리뷰 크롤링 → 규칙/sLLM → 자체 산식으로 초안  · 대안 일정 (보정 전/후)
가족 프로필 (생활형 질문)       ③ 규칙 엔진: 배치 검사 + 피로도 계산   · 부모님용 큰 글씨 카드
                               ④ LLM: 위반 이유·대안 설명 문장화
```

### 난이도 DB + HITL (담당자가 고칠 수 있는 구조)

```
관광지 속성 + 구글 리뷰 크롤링
            │
            ▼
 규칙 기반 키워드 분석 ──(판단 어려움)──▶ sLLM으로 부담 요소 추출
            │                                   │
            └──────────▶ 자체 산식으로 점수 계산 ◀┘
                                │
                                ▼
                  난이도 초안 (상/중/하 + 근거 리뷰)   [상태: 초안]
                                │
                                ▼
                     [관광지 난이도 DB] ◀── 가이드·MD 검수: 승인 / 등급 변경 / 메모
                                │                         [상태: 확정]
                                ▼
                     규칙 엔진이 확정 등급을 우선 사용
```

- DB 필드: 관광지, 등급, 근거(리뷰 요약·계단·대기 등), 상태(초안/확정), 수정자, 수정일
- **확정 등급은 AI가 덮어쓰지 않는다**
- 새로 뜨는 관광지는 자동으로 초안이 생기고 **검수 대기 목록**에 올라간다
- 여행 후 "생각보다 힘들었어요" 피드백이 쌓이면 **재검토 요청**을 띄운다

### 역할 분리
- **규칙 우선**: 리뷰 키워드 분석, 난이도 점수 산식, 배치 검사, 피로도 계산
- **sLLM (보조)**: 규칙으로 판단하기 어려운 리뷰에서 부담 요소만 추출한다. 점수는 sLLM이 아니라 자체 산식이 매긴다
- **LLM**: 패키지 일정표 같은 비정형 입력 정리, 위반 이유·대안 설명 문장 생성

### 에이전트(챗봇)의 역할

> 기존 GTA처럼 대화로 항공 → 숙소 → 일정을 순서대로 짜는 **순차형 에이전트는 쓰지 않는다.**
> 에이전트는 서비스에 쌓인 정보를 **모두 읽을 수 있는 챗봇**으로, 화면 옆에 붙어 "질문에 답하고, 수정 요청을 대신 걸어 주는" 역할만 한다.

**읽을 수 있는 정보**
- 가족 프로필과 허용 피로도
- 현재 일정 (패키지 원본 / 보정본)
- 관광지 난이도 DB (등급, 근거 리뷰, 초안/확정 상태)
- 규칙 엔진 결과 (날짜별 피로도, 위반 지점, 대안)

**하는 일**

| 역할 | 예시 |
|---|---|
| ① 설명 | "왜 둘째 날이 '무리'야?" → 상 2곳 연속, 휴식 없음, 근거 리뷰를 인용해 답함 |
| ② 비교·조회 | "A 패키지랑 B 패키지 중 뭐가 덜 힘들어?", "이 사원 계단 많아?" |
| ③ 수정 요청 전달 | "셋째 날 좀 여유 있게" → 순서 변경·휴식 추가 같은 **정해진 수정 명령**으로 바꿔 규칙 엔진에 넘김 → 결과가 화면에 반영됨 |
| ④ 부모님용 설명 | "엄마한테 보낼 말로 바꿔줘" → 큰 글씨 카드 문구 생성 |

**하지 않는 일**
- 난이도 등급을 매기거나 바꾸지 않는다 (산식과 담당자 검수의 몫)
- 피로도를 직접 계산하지 않는다 (규칙 엔진의 몫)
- 일정을 처음부터 대화로 순서대로 짜지 않는다
- 수정은 규칙 엔진을 통과한 것만 반영된다. 챗봇이 규칙을 우회할 수 없다

> 한 줄 정리: **판단은 규칙과 DB가, 챗봇은 그 결과를 읽어서 설명하고 요청을 전달하는 창구.** 그래서 대화 흐름이 꼬여도 결과가 흔들리지 않는다.
- 판단은 규칙이 하므로 결과가 일관되고 토큰 비용도 낮다. 이도경 멘토가 말한 "일반 지도·에이전트와 다른 평가 점수와 판단 로직"이 바로 이 부분이다

## ④ 구현 계획: 개발할 핵심 기능과 팀원별 역할 (약 1분)

### 핵심 기능 (우선순위 순)
1. **관광지 난이도 DB + 검수 화면**: 데모 도시의 주요 관광지 30~50곳, 초안과 확정 상태 관리
2. **규칙 엔진**: 배치 검사, 하루 피로도, 대안 제시
3. **일정 입력**: 패키지 일정표 붙여넣기 → 방문지 목록
4. **결과 화면**: 피로도 그래프, 보정 전/후 비교, 부모님용 카드
5. **정보 조회형 챗봇**: 프로필·일정·난이도 DB·규칙 결과를 읽고 설명, 수정 요청을 정해진 명령으로 전달

### 팀원별 역할

| 이름 | 담당 | 이번 결과물 |
|---|---|---|
| 남재은 | AI·챗봇 | 정보 조회형 챗봇(데이터 읽기, 설명, 수정 요청 → 명령 변환), 일정표 정리, sLLM 부담 요소 추출, HITL 흐름 |
| 김천지 | 웹·서버·DB 통합 | 난이도 DB 스키마와 검수 화면, 결과 화면, 전체 연결 |
| 이지원 | 검증·보정 로직 | 배치 규칙 엔진, 피로도 산식, 대안 생성, 보정 전/후 비교 |
| 노희윤 | 여행 데이터·공유 경험 | 데모 도시 관광지 속성 수집, 구글 리뷰 크롤링, 규칙 키워드 사전·난이도 산식, 부모님 카드 |

### 실행 계획 & 협업 포인트
- 해커톤 안에서는 데모 도시 1곳, 관광지 30~50곳을 팀이 등급화하고 검수 흐름까지 시연한다
- **부족한 데이터**: 관광지 내부 계단·경사·대기 정보는 지역 편차가 크다. 특히 동남아가 그렇다. 이 부분은 리뷰 분석으로 초안을 만들고, **현지 가이드·MD 검수를 하나투어와 협업**해 보완하는 단계적 계획으로 제시한다
- 팀 강점: 2026 MIXUP AI 해커톤 2등. 같은 4명이 멀티에이전트 여행 플래너 GTA(LangGraph, 외부 API 7개, HITL)를 구현한 경험이 있다

## 멘토께 여쭤볼 질문 (피드백 시간용, 1~2개만)

1. 효도여행(50대 이상 부모님 동반) 패키지에서 **실제로 많이 나가는 지역**은 어디인가요? (데모 도시 확정용)
2. 관광지 난이도 **상·중·하 3단계**가 실무에서 쓸 만한 수준일까요? 검수는 현지 가이드와 MD 중 누가 현실적일까요?
3. "상 연속 금지, 상 뒤 휴식" 말고 **현장에서 쓰는 일정 배치 노하우**가 있을까요?

## 예상 질문 & 답

| 질문 | 답 |
|---|---|
| 왜 걸음 수로 안 재나요? | 관광지 내부 보행 데이터는 대부분 없어요. 3단계 등급과 규칙은 데이터가 부족해도 작동하고, 사람이 검수할 수 있어요 |
| 난이도는 누가 정하나요? | 관광지 속성과 구글 리뷰를 규칙 기반으로 분석하고, 애매한 건 sLLM으로 추출한 뒤 자체 산식으로 초안을 만들어요. 가이드·MD가 확정하고, DB에서 언제든 고칠 수 있어요 |
| 기존 GTA 에이전트는 왜 안 쓰나요? | 대화로 순서대로 짜는 방식은 중간에 흐름이 꼬이면 결과가 흔들려요. 판단은 규칙과 DB가 하고, 챗봇은 그 결과를 읽고 설명하는 역할로 좁혔어요 |
| 왜 LLM에 다 맡기지 않나요? | 규칙과 산식이 판단하면 같은 관광지엔 같은 등급이 나오고, 근거를 설명할 수 있고, 비용도 적게 들어요. sLLM은 규칙이 놓치는 표현을 잡는 보조 역할이에요 |
| 규칙의 근거는요? | 접근성 지침(보행 불편자는 100m, 지팡이 사용자는 50m마다 휴식 필요, UK Inclusive Mobility)과 자녀 후기("일정은 50%만")가 근거예요. 기본값은 문헌에서, 개인별 한도는 프로필로 보정해요 |
| 고령자로 한정하는 거 아닌가요? | 판단 기준을 "가족 중 가장 체력이 약한 사람"에 둬서 3대 가족, 유아 동반으로 확장할 수 있어요 |
