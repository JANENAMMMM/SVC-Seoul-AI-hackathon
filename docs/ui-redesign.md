# 반걸음 UI 재설계

운영자 평가 근거 → 고객 일정 조정·승인 → 부모님 공유를 하나의 서비스로 연결한다. 기존 `mockup/`, `design-system/`, `legacy/`는 수정하거나 재사용하지 않았다.

## 실행

새 worktree에서 아래 순서로 실행한다. `.env`를 복사하거나 수정하지 않는다. `--env-file`에는 기존 설정 파일의 **경로만** 지정한다.

```powershell
uv sync
Set-Location frontend
npm ci
npm run build
Set-Location ..
uv run --env-file "기존 프로젝트의 .env 절대경로" python -m uvicorn api.main:app --host 0.0.0.0 --port 8131 --no-access-log
```

- `http://localhost:8131/`: 기본은 **시연 데이터**. 실제 채점 기록과 실제 planner로 생성한 고정 시나리오이며, DB 쓰기와 유료 모델 호출이 없다.
- `http://localhost:8131/?live=1`: 실제 연결. 부모님 조건 → 여행 생성 → 변경안 → 승인 → 공유 링크·의견 저장.
- 개발 서버: 백엔드를 8131에서 실행한 뒤 `frontend/`에서 `npm run dev`. Vite 8130이 API를 같은 출처로 프록시한다.
- 다른 휴대폰에서는 같은 네트워크의 서버 IP·포트를 사용한다. `localhost` 링크는 다른 휴대폰에서 열리지 않는다. 외부 공개 운영은 별도의 HTTPS 배포·방화벽 설정이 필요하며 이번에 배포하지 않는다.
- 서버는 **단일 프로세스**로 실행한다. 운영자 세션과 호출 제한은 메모리 기반으로 재시작 시 만료된다. 다중 worker 운영은 공유 세션 저장소가 필요하다.

## 화면과 데이터

고객 PC는 조건 / 동선 / 조정 세 박스, 모바일은 동선 / 조정 / 조건 하단 탭을 사용한다. 처음에만 조건 입력을 크게 보여주고 이후 요약한다. 조정은 기존 `EditCommand`를 사용해 장소 제외·짧은 관람·하루 부담 완화·한식 빈도 변경을 지원한다. ‘꼭 갈 곳’은 배치·변경 후에도 유지되는지 서버에서 검사한다. 피할 부담 태그는 추천 기준이며, 완전 제거를 보장하지 않는다. 남아 있는 주의사항은 계속 표시한다.

고객의 변경은 해당 여행만 바꾼다. 공개 장소 점수는 MD 재채점 후 별도 승인해야 바뀐다. 미승인 변경안 취소와 승인 후 과거 일정 복원은 다르며, 후자는 구현 범위가 아니다. 승인 충돌은 여행 버전으로 검사한다.

운영자 평가 현황에는 실제 카탈로그, 네 차원·가중치, 인용된 자료 유형, 관람 방식별 차이, 기후 자료, 반복 실행·인용 검증·최종 점수 연결을 표시한다. 인용 항목 수는 독립 표본 수가 아니다. 최종 점수와 정확히 일치하는 유효 실행의 설명을 사용하며, 없으면 확인 필요로 표시한다. 과거 MD 제안에 당시 태그 스냅샷이 없으면 현재 태그로 과거 값을 추정하지 않는다.

### 날씨와 추정치 구분

- 월별 기후는 다낭의 과거 일 최고 체감온도 월평균이다. 관측 기간·출처를 표시한다.
- 월 선택은 자료 조회이며 자동 재채점이 아니다. 실제 채점에 사용한 월·조건은 인용 기록으로 확인한다.
- 여행일 실시간 예보·시간대별 더위 보정은 미연결이다.
- 지도 선은 방문 순서이며 도로 길찾기 결과가 아니다. 이동 시간은 거리 기반, 내부 보행은 점수·프로필 기반 예상이다.
- 하루 부담·연속 배치 가산은 설계 지표다. 고객 체감 검증이나 현장 측정 결과라고 표현하지 않는다.
- 실제 휴게 시설을 확인하지 않은 휴식 구간은 ‘휴식 시간 확보 · 실제 쉴 장소는 현장에서 확인’으로 표시한다.

## API·DB·권한

- `/api/ui/catalog`, `/api/ui/evidence/{id}`, `/sources`: 지도·점수·연결된 근거.
- `/api/ui/trips`: 서버에서 실제 일정을 생성하고 소유자 키를 한 번 반환한다. 이후 여행 조회·변경·의견 조회에 `X-Trip-Key`가 필요하다.
- `/trips/{id}/preview`, `/proposals/{fid}/approve|reject`: 소유자 확인과 버전 검사. 승인 전에는 확정 일정을 변경하지 않는다.
- `/trips/{id}/shares`, `/shares/{token}`, `/shares/{token}/opinions`: 승인 일정 스냅샷 공유. 부모님에게 나이·성별·식이 프로필·소유자 키는 공개하지 않는다. 링크를 가진 사람은 일정을 보고 버튼 의견을 보낼 수 있다.
- `/trips/{id}/opinions`, `/opinions/{id}/review`: 자녀 의견함. 의견만으로 일정이 변경되지 않는다.
- `/api/ui/md/session`: 서버의 `HITL_MD_TOKEN`과 비교 후 HttpOnly·SameSite 세션 쿠키 발급. 설정이 없으면 실패한다. 인증값은 서버 환경변수로 주입하며 프론트 번들에 포함하지 않는다.
- `/api/ui/md/evaluation`, `/md/feedback`, `/md/feedback/{id}`, `/md/feedback/{id}/rejudge|approve|reject`: MD 인증 후 사용. 유료 재채점은 명시적인 버튼에서만 실행한다. 선택 승인은 단건 API를 순차 호출하고 실패를 건별 표시한다.

**호환성 변경:** 소유자 검사가 없는 기존 `/api/hitl/*` 직접 호출은 새 앱에서 MD 세션을 요구한다. 고객 클라이언트는 `/api/ui/trips/*`로 전환해야 한다. 기존 profile·planner·scoring API는 유지한다. 외부 출처의 변경 요청을 차단한다. MD 점수 승인 후 오래된 개인 일정은 새 카탈로그로 다시 생성하도록 유도한다.

`supabase/migrations/20261104210000_ui_sharing.sql`은 `ui_trips`, `ui_proposals`, `ui_shares`, `ui_opinions`만 추가한다. 네 테이블은 RLS를 켜고 anon/authenticated 직접 접근을 차단한다. 소유자·공유 토큰은 DB에 SHA-256 해시로 보관한다. 승인 일정과 공유본은 버전으로 구분하며 이전 공유본에는 이전 버전임을 표시한다. 이번 버전은 로그인 계정 간 여행 동기화 대신 브라우저 세션의 소유자 키를 사용한다.

```powershell
uv run --env-file "기존 .env 경로" python scripts/ui_db.py inspect
# 아직 적용하지 않은 DB에서만 실행. 이미 적용된 파일을 수정·중복 실행하지 않는다.
uv run --env-file "기존 .env 경로" python scripts/ui_db.py apply
```

## 검증·시연

```powershell
uv run python -m pytest -q
uv run --env-file "기존 .env 경로" python scripts/verify_ui_runtime.py
Set-Location frontend
npm run build
npm run test:e2e
node scripts/record-demo.mjs
```

런타임 검증 스크립트는 실제 서버 8131과 DB를 사용하며 직접 생성한 여행·의견·공유·제안 행만 정리한다. 원래 데이터와 유료 모델은 건드리지 않는다. 브라우저 테스트는 설치된 Edge를 headless로 사용한다. 녹화에는 Playwright FFmpeg가 필요하다. 결과는 `frontend/artifacts/`와 `frontend/test-results/`에 저장하며 Git에서 제외한다.

55초 녹화 흐름: 0~6초 평가 현황 → 6~14초 기후·자료 근거 → 14~20초 검증 → 20~27초 고객 동선 → 27~40초 변경안·등급 상→중 → 40~47초 승인 → 47~55초 부모님 공유. 화면은 실제 앱과 동일하며 시연 데이터 표시를 유지한다. WebM 리허설 영상은 최종 PPT에 넣기 전 재생·포맷 호환성을 확인한다.

시연 fixture를 갱신하려면 `scripts/build_ui_fixture.py`를 실행한다. 실제 planner와 로컬 채점 기록을 사용하며 DB는 인용 자료 조회만 한다. `frontend/public/demo.json`은 개인정보·비밀값이 없는 공개 시연 스냅샷이다.

고정 시나리오는 오행산에서 출발하는 기존 표준 관람 일정이다. 부모님 보행 응답은 15~30분, 엔진의 연속 보행 기준은 20분으로 구분한다. 오행산을 제외하지 않고 짧은 관람으로 바꾸면 실제 엔진 결과에서 부담 상→중, 예상 보행 74→65분, 별도 휴식 1회를 유지한다. 원래 일정의 표준 관람은 명시적 관람 방식 선택값이며, 새 일정 자동 생성의 기본 추천이라고 표현하지 않는다.

실시간 예보·가격·예약·음성·승인 후 복원은 후속 범위다. 자동 지도 타일과 웹 폰트는 네트워크가 필요하며, 미로딩 시 기본 배경·시스템 폰트로 동선과 화면을 유지한다.

## 이번 구현의 확인 결과

- 백엔드 pytest 228개 통과, 프론트 타입 검사·프로덕션 빌드 통과.
- Edge headless에서 PC 핵심 여정, 390px 모바일, 미인증 MD 차단, 두 분 조건 입력, MD 선택 승인 부분 실패, 1100px 등급 표시, 지도 실패 대체, 시연 검수 기록 이동까지 8개 브라우저 시나리오 통과. MD 선택 승인 테스트는 응답을 모의하며 공개 점수를 실제 변경하지 않는다.
- 실제 DB·HTTP에서 소유자 권한, 미승인 일정 유지, 승인·중복 승인·오래된 제안 차단, 별도 부모님 클라이언트의 의견 등록, 자녀 조회·확인, 조건 변경 버전 충돌, 공유본 이전 버전 표시와 RLS 확인. 직접 만든 테스트 행만 정리했다.
- 새 UI 테이블 4개 마이그레이션 적용 후 실제 구조·RLS 확인. 기존 공유 테이블은 삭제·구조 변경하지 않았다.
- 유료 모델 호출, 실제 공개 점수 재채점·승인, 실제 휴대폰 기기·외부 배포·PPT 재생 검증은 이번에 수행하지 않았다.
- 기존 환경에 `HITL_MD_TOKEN`이 없어 실제 MD 로그인은 비활성 상태다. 인증·만료·로그아웃은 테스트용 서버 설정으로 확인했으며 실제 `.env`는 수정하지 않았다.


## 화면 재검토 반영

하나투어 공식 홈(https://www.hanatour.com/v2/home)을 브라우저로 확인하고, 흰 배경·짙은 본문·보라색 강조·기능 중심 메뉴와 탭을 참고했다. 공식 로고나 이미지 자산은 사용하지 않았다. 슬로건·영문 장식·단계 번호를 줄이고 실제 기능명으로 바꿨다.

- 운영자: 1200px 이하에서 등급을 숨기던 규칙을 수정했다. 1100px에서도 목록의 상·중·하를 확인했다. 네 평가 항목 요약과 출처, 과거 기후를 먼저 보여준다. 다중 내부 스크롤을 줄이고 목록만 고정한다.
- 지도: 브라우저 이미지 요청에 origin 참조 주소를 명시하고 OSM 공식 타일 주소를 사용한다. 서버 설정은 바꾸지 않았다. 실제 타일 8개 모두 HTTP 200과 origin 참조 주소를 확인했다. 타일 로딩 실패 시 정책 오류 이미지 대신 배경 연결 안내와 장소 위치·방문 순서를 유지한다. 기존 지도를 재생성하지 않고 마커·동선을 갱신한다.
- 지도 라벨: 세로로 눌리는 폭을 수정했다. 장소마다 번호·등급을 붙이고 선택한 장소의 이름과 주의 태그를 펼쳐 표시한다.
- 고객: 조건 → 조정안 → 승인 → 부모님 공유 흐름을 PC와 390px 화면에서 다시 확인했다. 고객 화면의 불필요한 엔진·AI 호출 설명을 줄였다.
- 운영자 검수 시연: 실제 확인 필요 관광지를 대상으로 검수 완료·기록 이동을 체험한다. 시연 상태만 저장하며 원본 평가와 공개 점수는 바꾸지 않는다.
- 검증: 타입 검사·빌드, 브라우저 시나리오 8개 통과. 여기에는 1100px 등급 표시, 강제 지도 실패 처리, 시연 검수 기록 이동이 포함된다. 390px 가로 넘침 없음도 확인했다.
